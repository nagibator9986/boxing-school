# AINAZAROV TOP TEAM — AI-консультант

Чат-бот-консультант школы бокса и кикбоксинга в Костанае. Отвечает родителям в WhatsApp и
Instagram Direct через агрегатор [Wazzup24](https://wazzup24.com), консультирует по залам, ценам
и условиям, считает стоимость абонементов с семейными скидками, записывает на бесплатное пробное
занятие и передаёт диалог живому менеджеру, когда данных не хватает.

Языки: русский и казахский с автоопределением, включая смешанную речь в одном сообщении.
Модель: Google Gemini. Деплой: Railway.

---

## Главный принцип

**Бот не выдумывает.** Ни одна цифра, адрес, время или номер телефона не попадают клиенту иначе,
чем из результата детерминированного инструмента. Модель отвечает только за выбор инструмента,
формулировку, тон и язык — считает и ищет обычный Python поверх YAML.

Контур держится на трёх опорах:

1. **Восемь инструментов, пять из них полностью детерминированные.** `calculate_price` не спрашивает
   модель, сколько будет 25 000 минус 10 % — он считает сам.
2. **Пост-фильтр перед отправкой** (`app/core/postcheck.py`). Каждое число-цена, адрес, время и
   телефон в ответе модели сверяются с данными, которые вернули инструменты на этом ходу.
   Не подтвердилось — сообщение не уходит, вместо него мягкая эскалация на менеджера.
3. **База знаний как единственный источник фактов.** `kb/*.yaml` редактирует владелец школы без
   программиста; ни промпт, ни код при этом не трогаются.

Отдельно стоит `get_schedule`: расписания в данных пока нет, и инструмент всегда возвращает
`no_data`. Он существует ровно затем, чтобы модель не сочинила время занятий. Как только расписание
появится в `kb/gyms.yaml`, инструмент начнёт отдавать его сам — правка кода не нужна.

## Поток обработки сообщения

```
Wazzup webhook  →  FastAPI (только валидация + постановка в очередь, ответ 200 за миллисекунды)
                       ↓
                    очередь arq
                       ↓
   дедуп по messageId  →  фильтр эха / детекция входа оператора  →  пауза бота
                       ↓
   склейка серии сообщений (debounce) + лок диалога
                       ↓
   определение языка RU/KK  →  нормализация сленга  →  guards (prompt injection, off-topic)
                       ↓
   Gemini + ручной цикл вызова инструментов (до 5 витков)
                       ↓
   пост-фильтр  →  outbox  →  воркер отправки  →  Wazzup
```

Всё, что уходит клиенту, проходит через `outbox` — прямых отправок из пайплайна нет. Это даёт
идемпотентность (повторная попытка не даёт клиенту дубль) и переживает рестарт контейнера.

## Структура

| Каталог | За что отвечает |
|---|---|
| `app/types.py` | Все типы, пересекающие границы модулей. Импортировать отсюда, не дублировать |
| `app/config.py` | `Settings` (pydantic-settings) — единственный вход для настроек, 72 поля |
| `app/api/` | HTTP: вебхук, `/healthz`, `/readyz`, `/metrics`, раздача медиа, админка |
| `app/channels/` | Wazzup24: схемы вебхука, HTTP-клиент, нормализация входящих, правила каналов |
| `app/core/` | Пайплайн, дедуп, debounce, сессия, пауза, язык, лексикон, guards, пост-фильтр |
| `app/llm/` | Единственное место, где импортируется `google.genai`. Клиент, промпт, цикл инструментов |
| `app/tools/` | Восемь инструментов. Здесь живут все расчёты и поиск по фактам |
| `app/kb/` | Загрузка, валидация и рендер базы знаний; реестр пробелов в данных |
| `app/storage/` | SQLAlchemy 2.0, репозитории, TTL-состояние поверх SQLite |
| `app/workers/` | arq: обработка входящих, отправка outbox, follow-up |
| `app/notify/` | Лид-карточка и уведомления менеджеру |
| `kb/` | **Семь YAML — факты о школе.** Редактируются без программиста |
| `media/` | Файлы-артефакты (фото прайса и т. п.), раздаются по подписанной ссылке |
| `crm/` | **Веб-интерфейс управления ботом**: база знаний, расписание, клиенты, настройки |
| `docs/` | Аудит контента, архитектура, контракт интерфейсов, исследования, инструкции |

## Локальный запуск

```bash
make venv           # .venv + зависимости
cp .env.example .env
make bot            # бот в Telegram
make crm            # управление ботом: http://127.0.0.1:8000
```

Бот и CRM — разные процессы и работают независимо: CRM правит файлы базы знаний
и настройки, бот замечает правки сам, в течение секунды. Останавливать бота на
время работы в CRM не нужно. Подробности: [docs/CRM.md](docs/CRM.md).

Продовый путь через Wazzup поднимается отдельно:

```bash
make migrate        # alembic upgrade head
make run            # только API
make worker         # только фоновый воркер (arq, нужен Redis)
```

Реальные ключи для локальной работы не нужны: при `APP_ENV=local` блокеры старта не проверяют
`WAZZUP_API_KEY` и `GEMINI_API_KEY`, база по умолчанию — SQLite.

## Проверки

```bash
make test           # 521 тест, около 5 секунд
make kb-validate    # проверка kb/*.yaml с человекочитаемым отчётом
make lint           # ruff
.venv/bin/python scripts/smoke.py   # сквозной прогон пайплайна на FakeLLMClient, без сети
```

`scripts/smoke.py` прогоняет синтетический вебхук Wazzup через весь пайплайн и печатает, что бот
собрался ответить и какие инструменты вызвал. Отдельно проверяет, что эхо не порождает ответ,
дедуп держит один ответ, а собственное эхо отбрасывается.

Что покрыто тестами: калькулятор на всех тарифах и границах, пост-фильтр в обе стороны (и пропуск
выдумки, и ложное срабатывание), эхо-фильтр и детекция оператора, дедуп и конкурентность, цикл
вызова инструментов с сохранением thought signatures, вебхук, нормализация `DATABASE_URL`,
валидация базы знаний и архитектурные правила слоёв.

## Где что менять

**Факты о школе — только в `kb/*.yaml`.** Не в коде и не в промпте. Цены, адреса, ответы на вопросы,
системные фразы, лексикон разговорных форм.

Руками их править не нужно: для этого есть CRM (`make crm`) и админка в Telegram
(`/admin`). Оба интерфейса пишут одни и те же файлы и делают это одинаково —
резервная копия, атомарная запись, полная валидация, откат при любой ошибке.
При правке файла вручную проверяйте себя через `make kb-validate`.

**Новый инструмент:** реализация в `app/tools/`, регистрация в `app/tools/registry.py`
(имя, флаг `is_deterministic`, JSON-схема), после чего он автоматически попадает в объявления
для модели. `app/llm` про `app/tools` ничего не знает — их связывает `app/core/pipeline.py`.

**Правило зависимостей**, которое стережёт `tests/test_layering.py`:

- `google.genai` импортируется **только** внутри `app/llm/*`;
- `app/llm` не импортирует `app/tools`, `app/tools` не импортирует `app/llm`;
- `app/tools` ничего не знает про Wazzup, `app/channels` — про Gemini.

**Тайминги связаны жёстко** и проверяются при старте (`Settings.timing_blockers`):
ход модели `LLM_TURN_BUDGET_S` < TTL лока диалога `CONV_LOCK_TTL_SECONDS`, а таймаут задачи
воркера больше суммы ожидания лока и хода. Рассогласование стоит клиенту второго ответа на неполной
истории, поэтому приложение откажется стартовать, а не будет чинить это в проде.

## Деплой

Railway, **одна служба**: бот в Telegram и CRM работают в одном контейнере под
надзирателем `scripts/serve.py`, потому что делят базу знаний и базы SQLite —
диск на Railway между службами не разделяется. База знаний живёт на диске, а не
в образе, поэтому передеплой не стирает правки владельца.

Пошагово: [docs/DEPLOY-RAILWAY.md](docs/DEPLOY-RAILWAY.md).
