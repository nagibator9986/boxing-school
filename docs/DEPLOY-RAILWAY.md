# Развёртывание на Railway — AINAZAROV TOP TEAM

Одна служба, один диск, ~15 минут. После этого бот отвечает клиентам в Telegram
круглосуточно, а CRM открывается по адресу вида `https://<имя>.up.railway.app`.

---

## Почему одна служба, а не две

Бот и CRM работают с **общими файлами**: база знаний `kb/*.yaml` и базы SQLite
(диалоги, состояние, настройки). Диск на Railway принадлежит одной службе и
между службами не разделяется.

Разнеся их на две службы, мы получили бы две независимые копии базы знаний:
владелец правит цену в CRM, а бот отвечает по своей старой копии и никогда об
этой правке не узнает. Поэтому в контейнере работает надзиратель
`scripts/serve.py`: он поднимает CRM под gunicorn на `$PORT` и бота рядом,
следит за обоими и останавливает службу целиком, если один из них упал —
перезапуском занимается Railway.

## Почему база знаний живёт на диске, а не в образе

Образ пересобирается при каждом передеплое. Если бы бот читал `kb/` из образа,
любой передеплой возвращал бы цены, расписание и ответы к состоянию репозитория
и стирал бы всё, что владелец наменял через CRM за неделю — молча.

Поэтому при первом запуске файлы копируются из образа на диск, а дальше
действует одно правило: **файл с диска важнее файла из образа**. Новые файлы
следующих релизов дописываются, существующие не трогаются никогда.

## 1. Что подготовить

| Что | Где взять |
|---|---|
| Аккаунт Railway | railway.app, вход через GitHub |
| Репозиторий на GitHub | Railway разворачивает из него |
| Токен бота Telegram | @BotFather → `/newbot` (или `/token` для существующего) |
| Ключ Gemini | Google AI Studio → API keys. Нужен **Tier 1+**: бесплатный не выдержит поток |
| Пароль для CRM | Свой, а не `Azamat65`: адрес CRM публичный |
| Ключ сессий | `python -c "import secrets;print(secrets.token_hex(32))"` |

---

## 2. Создать службу

1. **New Project → Deploy from GitHub repo**, выбрать репозиторий.
2. Railway найдёт `railway.json` и соберёт образ по `Dockerfile`. Первая сборка
   идёт 3–5 минут.
3. **Settings → Networking → Generate Domain** — появится публичный адрес.

## 3. Подключить диск

**Settings → Volumes → Add Volume**, точка подключения — **`/data`**.

Без диска служба всё равно поднимется, но данные будут жить внутри контейнера и
пропадать при каждом передеплое: история диалогов, заявки, права
администраторов, все правки базы знаний. Если том подключён по другому пути,
запуск остановится с явным сообщением — это лучше, чем тихая потеря.

## 4. Задать переменные

**Variables → Raw Editor**, вставить и подставить свои значения:

```
TELEGRAM_BOT_TOKEN=8661326968:AA...
GEMINI_API_KEY=AQ...
ADMIN_PASSWORD=<свой пароль, не Azamat65>
CRM_SECRET_KEY=<64 символа из команды выше>
DATA_DIR=/data
APP_ENV=prod
TZ=Asia/Almaty
```

Пока этого достаточно: бот работает в Telegram, CRM открывается на `/crm`.
WhatsApp и Instagram подключаются отдельно — раздел 7.

Необязательное:

```
KB_WATCH_INTERVAL_S=5     # как часто бот сверяет базу знаний с диском
CRM_THREADS=4             # потоков у веб-интерфейса
RUN_BOT=true              # false — поднять только CRM
RUN_CRM=true              # false — поднять только бота
GEMINI_MODEL_PRIMARY=gemini-3.5-flash-lite
```

После сохранения служба перезапустится сама.

## 5. Проверить

```bash
curl https://<имя>.up.railway.app/healthz
```

Ответ `{"kb":"5eb33e48d15f","status":"ok"}` означает, что CRM жива и база знаний
читается. Сама CRM открывается по адресу `https://<имя>.up.railway.app/crm`
(корень домена туда перенаправляет). `"kb":"invalid"` — база знаний на диске сломана: CRM работает, бот
отвечать не сможет, чинить в разделе «Файлы базы».

В журнале службы при удачном старте:

```
[serve] каталог данных: /data
[serve] kb: скопировано из образа файлов — 7 (существующие не тронуты)
[serve] схема базы диалогов на месте
[serve] база знаний в порядке: версия 5eb33e48d15f, залов 14
[serve] Wazzup: приём выключен — WAZZUP_API_KEY не задан
[serve] Telegram и CRM работают как обычно.
[serve] веб-служба: http://0.0.0.0:8080 — CRM на /crm, вебхук Wazzup на /wazzup/webhook/…
[serve] бот Telegram: опрос запущен
Бот @ainazarov_kickboxing_bot запущен
```

Дальше: открыть адрес в браузере, войти паролем, и написать боту в Telegram —
он должен ответить.

## 6. Стать администратором

Отправить боту в Telegram пароль из `ADMIN_PASSWORD`. Права сохранятся на диске.
После этого приходят карточки заявок и работает `/admin` в чате.

## 7. Подключить WhatsApp и Instagram (Wazzup)

Служба уже умеет принимать вебхуки: CRM и приём Wazzup работают в одном процессе
на одном порту. Пока `WAZZUP_API_KEY` пуст, приём просто не поднимается, и в
журнале об этом сказано прямо.

Добавьте переменные:

```
WAZZUP_API_KEY=<ключ из кабинета Wazzup24>
WAZZUP_WEBHOOK_SECRET=<32 случайных символа>
PUBLIC_BASE_URL=https://<имя>.up.railway.app
MANAGER_NOTIFY_TARGET=77XXXXXXXXX
MANAGER_NOTIFY_CHANNEL_ID=<id канала из Wazzup>
WAZZUP_CHANNEL_ID_WHATSAPP=<id канала WhatsApp>
WAZZUP_CHANNEL_ID_INSTAGRAM=<id канала Instagram>
INLINE_WORKER=true
WAZZUP_REGISTER_WEBHOOK_ON_START=true
```

Где что взять:

| Переменная | Откуда |
|---|---|
| `WAZZUP_API_KEY` | Wazzup24 → Интеграции → Интеграция с CRM → API → Дополнительно. **Тариф платный**, на бесплатном API закрыт |
| `WAZZUP_WEBHOOK_SECRET` | свой: `python -c "import secrets;print(secrets.token_urlsafe(32))"`. Не короче 24 символов — иначе служба не стартует |
| `MANAGER_NOTIFY_TARGET` | номер, куда падают карточки заявок: `77XXXXXXXXX`, только цифры |
| `MANAGER_NOTIFY_CHANNEL_ID`, `WAZZUP_CHANNEL_ID_*` | `GET https://api.wazzup24.com/v3/channels` с заголовком `Authorization: Bearer <ключ>` |

Адрес вебхука собирается сам:

```
https://<имя>.up.railway.app/wazzup/webhook/<WAZZUP_WEBHOOK_SECRET>
```

При `WAZZUP_REGISTER_WEBHOOK_ON_START=true` служба пропишет его в Wazzup сама
при старте. Иначе впишите руками в кабинете.

Проверка: `curl https://<имя>.up.railway.app/healthz`. Если приём поднялся,
в журнале будет `[serve] Wazzup: приём включён`; если нет — там же причина.

**Клиенту бот отвечает в тот канал, откуда пришло сообщение** — id берётся из
самого вебхука. Переменные `WAZZUP_CHANNEL_ID_*` нужны только исходящим
карточкам менеджеру.

## Что происходит при передеплое

1. Railway собирает новый образ и запускает контейнер.
2. `scripts/serve.py` находит на диске уже существующие `kb/` и `media/` и
   **ничего не перезаписывает** — правки владельца остаются.
3. Файлы, которых на диске нет (новые в этом релизе), дописываются.
4. Бот и CRM стартуют на тех же базах SQLite.

Проверено имитацией: цена, изменённая через CRM на 27 000, пережила пересборку
образа, в котором лежало прежнее значение 25 000.

## Обновление базы знаний из репозитория

Если нужно **принудительно** взять файл из репозитория (например, вы правили
`kb/faq.yaml` в коде и хотите, чтобы он поехал в прод), удалите этот файл на
диске — при следующем запуске он приедет из образа. Отдельной кнопки для этого
нет намеренно: такое действие стирает правки владельца, и делать его случайно
не должно быть возможно.

## Стоимость и режим

- Бот работает **опросом** (long polling): процесс живёт постоянно, поэтому
  «спящий режим» надо держать выключенным (`sleepApplication: false` уже
  прописан в `railway.json`).
- Расход Gemini — около $0,005 за ход диалога, примерно $35 в месяц на 1000
  диалогов.
- Одна реплика (`numReplicas: 1`) — обязательно. Второй экземпляр начал бы
  опрашивать Telegram параллельно и получал бы `Conflict: terminated by other
  getUpdates request`, а два процесса писали бы в один файл SQLite.

## Ограничения этой конфигурации

- Одна реплика обязательна. Два экземпляра начали бы опрашивать Telegram
  параллельно и писать в один файл SQLite.
- `INLINE_WORKER=false` в этой конфигурации не имеет смысла: отдельная служба
  воркера не получит доступ к тому же диску.
- Процесс в контейнере работает под root: том Railway монтируется с правами
  root, и непривилегированный процесс не смог бы в него писать.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `Application failed to respond` | CRM не поднялась. Смотреть журнал: скорее всего не задан `DATA_DIR` либо том подключён не к `/data` |
| В журнале «каталог данных недоступен на запись» | Том не подключён. Settings → Volumes, точка подключения `/data` |
| `"kb":"invalid"` в `/healthz` | База знаний на диске сломана. Открыть CRM → «Файлы базы», найти ошибку из журнала |
| Сообщения WhatsApp не доходят | В журнале ищите `Wazzup: приём выключен` — там названа причина. Проверьте, что адрес вебхука в кабинете Wazzup совпадает с `PUBLIC_BASE_URL` и секретом |
| Бот не отвечает, CRM работает | Не задан `TELEGRAM_BOT_TOKEN` — в журнале будет «бот не запущен» |
| `Conflict: terminated by other getUpdates` | Запущено две реплики либо локальный бот на том же токене. Оставить один |
| Вход в CRM слетает после каждого передеплоя | Не задан `CRM_SECRET_KEY` |
